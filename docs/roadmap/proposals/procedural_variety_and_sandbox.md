# 『DS1ish』 プロシージャルマップの多彩化構想とプリセット共有・バランス設計資料

本書は、1984年 PC-8801版『ドラゴンスレイヤー (Level 2.0)』のコアメカニクスをベースとした拡張Web実装『DS1ish』における、**「知的で単調にならないプロシージャルマップ生成の工夫」**、**「マップトポロジーと連動した難易度・ゲームバランス調整パラメータ体系 (`DungeonTuningParams`)」**、および**「シード＆設定プリセット共有（`MapPresetManager` / `DS1MAP:`）とヘッドレス評価の連携」**の構想・設計仕様をまとめたドキュメントである。

---

## 1. 構想の背景と基本方針

### 1.1 固定ステージを持たないプロシージャルマップ生成方式
本作では原作の固定ステージマップを複製・収録せず、**「原作の魅力であるルール（8方向移動・4方向戦闘、ブロック押しパズル、首討伐と世界変化、王冠運搬）をベースに、ダンジョンマップのプロシージャル（自動）生成とシード共有によって多彩な迷宮を遊べるファンメイド・オマージュ作品」**として設計している。

### 1.2 手動のタイル編集ではなく「生成パラメータ × シード共有」
64×64（4,096マス）の迷宮を手動で1マスずつ配置・編集するアプローチは採らず、**「解法性が100%保証されたプロシージャル生成アルゴリズム（6種トポロジー × 9セクター動的配置 × 4大アーキタイプ）をベースとし、シード値とバランス設定の組み合わせで多様な迷宮を生成・保存・共有する」**方式を採用する。

### 1.3 個別数値の場当たり的修正ではなく「マップ構造 × バランスパラメータ」の統合制御
テストプレイにおいて確認された以下のゲームバランス上の課題は、いずれもマップの形状（トポロジーや密度）と密接に関わっている：
1. **後半の「我が家からの敵湧き」が全体上限で停止する問題**:
   - `SpawnSystem.ts` の全体同時生存上限（首0本=7〜首3本=13）に遠方の残存敵が張り付くことで、首討伐後のクライマックスであるはずの「家からの敵スポーン（`spawnFromHome`）」がブロックされ、家の周囲が空いていても魔物の巣窟にならない。
2. **経験値（EXP）上昇カーブの極端なインフレ階段**:
   - `Enemy.ts` の獲得経験値式 `floor(baseDef / 2) + 50` により、終盤の高DEFモンスターを1体倒すだけでEXPが10万〜26万単位で跳ね上がる。EXPは最大HPと被ダメージ軽減（実質DEF）を兼ねているため、パワーストーンによるSTR上昇と同様に「0か100か（ノーダメ無双か即死か）」の極端な二極化になりやすい。
3. **非消耗アイテム（鍵・指輪・十字架）の無制限排出とゴースト数の管理**:
   - 宝箱（`ChestSystem.ts`）から 1/8 の確率で装備品（十字架・指輪・鍵）が無制限に排出されるため、特に無敵・結界効果を持つ「十字架」が出すぎるとゲーム性が崩壊する。また、マップの広さや通路幅に応じてゴースト（おばけ）の適正数も異なる。

これらを個別のハードコード定数で場当たり的にいじるのではなく、**「完成した全体マップの構造（トポロジー・導線・密度）を俯瞰しながら、マップ構成に応じた難易度調整パラメータ（`DungeonTuningParams`）を一元的に制御・シミュレーション評価する」**アプローチをとる。

## 2. 生成されるマップの多彩な工夫（バリエーション設計）

単なる「正方形の部屋と通路がランダムに並ぶ」だけでは、ドラスレ特有の「倉庫番パズル」「墓の陣取り」「王冠運搬サバイバル」の面白さを引き出せない。以下のテーマやギミックをプロシージャル生成に組み込む。

### 2.1 地形トポロジー（ダンジョン形状）のバリエーション

```
【代表的な地形パターン】
(A) スタンダード部屋・回廊       (B) ピラー・市松模様             (C) スパイラル・迷宮
┌───────────┬───────────┐       ┌───────────────────────────┐       ┌───────────────────────────┐
│ [HOME]    │           │       │ ▣   ▣   ▣   ▣   ▣   ▣ │       │ ┌───────────────────────┐ │
│   ┌──┐    │   ┌──┐    │       │                           │       │ │ ┌───────────────────┐ │ │
│   │  │    └───┘  │    │       │ ▣   ▣   ▣   ▣   ▣   ▣ │       │ │ │ ┌───────────────┐ │ │ │
├─  └──┘  ─────────┴───┤       │                           │       │ │ │ │   [DRAGON]    │ │ │ │
│           [DRAGON]    │       │ ▣   ▣   ▣   ▣   ▣   ▣ │       │ │ │ └───────────────┘ │ │ │
└───────────────────────┘       └───────────────────────────┘       └─┴─┴───────────────────┴─┴─┘
```

1. **スタンダード部屋・回廊型 (`STANDARD_ROOMS`)**:
   - 大小さまざまなブロック壁の小部屋が通路で結ばれた王道型。
   - 部屋の境界に扉のような1マスの隙間を意図的に作り、指輪でブロックを詰めて部屋全体を安全地帯にできるパズル性を持たせる。
2. **ピラー・市松模様型 (`PILLAR_GRID`)**:
   - 1マスまたは2マスおきにブロックが規則正しく並ぶ広大な柱型フロア。
   - 視界が開けているためモンスターと頻繁に遭遇するが、斜め移動の隙間や岩押し退避路が無数にあり、プレイヤースキルが強く試される。
3. **幅1マスのクラシック迷路型 (`NARROW_MAZE`)**:
   - 通路幅がちょうど1マス（壁の厚みも1マス）で入り組む純粋なクラシック迷路。
   - **ゲーム的特徴**:
     - 直線が続くため敵とすれ違いができず、正面衝突か後退を迫られる極度の緊張感。
     - 斜め移動による回避が封じられるため、角やT字路の利用が必須。
     - **ショートカット開拓の快感**: 壁1枚を隔てて隣接通路が走っているため、`BREAK` 魔法で壁（ブロック）を消滅させると長大な迂回路が一瞬で直通ハイウェイに変わる、ドラスレ屈指の掘削カタルシスを生む。
     - `FREEZE` 魔法で凍らせた敵が完全な「通行止めストッパー」として機能する。
4. **スパイラル・渦巻き型 (`SPIRAL_LABYRINTH`)**:
   - 外周から中央のドラゴン巣窟に向かって渦巻き状に通路が伸びる構造。
   - 我が家（外周）とドラゴン（中央）の物理的距離は近いが、ブロックを掘削（BREAK）しない限り長距離の周回を強いられる。王冠運搬時にショートカット用のトンネルを掘る戦略が熱い。
5. **アリーナ・要塞型 (`FORTRESS_ARENA`)**:
   - 中央にドラゴンの広い空間（コロシアム）があり、周囲に堅牢な小部屋群が防壁のように配置されている。

### 2.2 複合セクター（マルチトポロジー混在）生成方式

原作の豊かで有機的なマップ（「北西は部屋、北東は柱、南西は回廊、中央はドラゴン広場」）をプロシージャルで再現するため、**1枚の64×64マップの中に複数のトポロジーをモザイク状に混在**させて生成する。

```
┌───────────────────────────┬───────────────────────────┐
│ [セクターA: 小部屋＆狭路]   │ [セクターB: ピラー・市松柱]  │
│ ┌──┐   ┌──┐    ┌────────┐ │ ▣   ▣   ▣   ▣   ▣   ▣   │
│ │  │   │  │    │ [HOME] │ │                           │
│ └──┘   └──┘    └────────┘ │ ▣   ▣   ▣   ▣   ▣   ▣   │
├───────────────────────────┼───────────────────────────┤
│ [セクターC: 幅1マス迷路]   │ [セクターD: ドラゴンアリーナ] │
│ ┌─┬───┬─┐   ┌─────────┐   │         ┌───┐             │
│ │ └─┐ │ │   │(パンドラ)│   │         │   │             │
│ └───┘ └─┘   └─────────┘   │       [DRAGON]          │
└───────────────────────────┴───────────────────────────┘
```

1. **セクター分割とトポロジー割り当て**:
   - 64×64マップを4〜9分割のセクターに区分。
   - 例: 「我が家セクター（安全小部屋）」＋「探索セクター（幅1マス迷路）」＋「アクションセクター（ピラー柱）」＋「決戦セクター（アリーナ）」。
2. **セクター間ゲート（接続部）のパズル化**:
   - セクター同士の境界に1〜2マスのボトルネック通路を設け、そこに初期配置のブロックを1個置いておく。
   - 指輪でブロックを1回押して「開通」させたり、逆に敵ラッシュ時にブロックを詰めて「隔離」する陣取りの醍醐味が自然に発生する。
3. **セクター間ワープネットワーク (`SECTOR_WARP_PAIRS`)**:
   - セクター同士を結ぶワープゾーン（WARP）を計画的にペアリング配置。
   - **メンタルマップの整理**: 「あのワープはピラーセクターに飛ぶ」「迷路最深部のワープはドラゴン近郊へ直通する」など、プレイヤーが地図を直感的に把握可能。
   - **飛び地（孤立隠し部屋）の開拓**: 徒歩では進入できない密閉セクターへの唯一の突入ルートとして機能。
   - **脱出時のエスケープルート**: 王冠回収時に敵で正面通路が塞がれた際、緊急離脱して我が家周辺セクターへワープする迂回ルートとして機能。

### 2.3 オブジェクト・資源配置の戦略的工夫

1. **「初期ブートストラップ（序盤導線）」の動的変化**:
   - **安全型**: 家の目の前に剣・鍵・指輪が揃っており、すぐに戦闘態勢に入れる（入門向け）。
   - **潜入型**: 剣が少し離れたブロックの奥にあり、モンスターを避けて丸腰でスニーキングして回収するスリル設計。
2. **「パンドラの墓場（集中密集墓地）」ギミック**:
   - 墓が均等に散らばるのではなく、特定の区画に4〜6個集中配置された「デンジャーゾーン」。
   - 事前に十字架やブロックで封鎖できれば一気に安全になるが、放置するとそこから大量の敵が湧き出すハイリスク・ハイリターンな陣取りスポット。
3. **「閉鎖された宝物庫（密室空間）」**:
   - 四方をブロックで完全に密閉された空間内に、貴重なパワーストーンや魔法の壺を集中配置。
   - 最初は入れないが、指輪でのブロック押し、ゴーストによるアイテム運び出し、あるいは中盤の `BREAK` 魔法習得によって一気に開拓できる「成長の達成感」を与える。
4. **「ドラゴンの巣窟（Dragon Lair）」の防衛地形**:
   - ドラゴンの周囲を適度にブロックで囲み、火炎弾が遠くまで届かない射線遮蔽物を用意する（初心者救済）。
   - 逆に上級者向けには射線が完全に開通しており、斜め接近ルートの構築が必須となる地形。

### 2.4 王冠回収（脱出フェーズ）を意識した導線設計

ドラゴン討伐後に発生する「我が家への敵ラッシュ＋王冠散乱」を最高に面白くするため、生成アルゴリズム側で以下の配慮を行う。

* **帰還ルートの複線性（チョークポイントの配置）**:
  - 我が家とドラゴンの間に「ボトルネック（幅1マスの狭路）」を自然に生み出す。
  - プレイヤーは脱出時にこの狭路に `FREEZE` で敵を凍らせて栓をするか、あるいは別ルートを掘削するかを選択する。

## 3. トポロジー連動型・難易度調整パラメータ体系 (`DungeonTuningParams`)

テストプレイで浮き彫りになった3大課題（家湧き停止、EXP急騰インフレ、非消耗品・ゴースト数制御）をマップ構造と一体で管理するため、各ダンジョンデータに `DungeonTuningParams` を持たせる。未指定の項目はトポロジーと難易度（EASY / NORMAL / HARD）に応じた推奨プリセット値が自動適用される。

### 3.1 課題1への対策：スポーン上限と「我が家からの敵湧き」専用枠 (`spawnConfig`)

#### 問題の所在
現行の `SpawnSystem.ts` では、墓からの通常スポーンも首討伐後の家からのスポーン（`spawnFromHome`）も同一の `getMaxActiveEnemies(headsKilled)`（首0本=7, 1本=9, 2本=11, 3本=13）で頭打ちになっている。そのため、64×64の遠隔地に敵が残存していると、首を倒しても我が家から一切敵が湧かず、「家が魔物の巣窟と化す」クライマックスの緊張感が失われる。

#### 解決メカニズム
1. **家湧き専用リザーブ枠 (`homeSpawnReserveSlots`)**:
   - 通常のフィールド墓湧き上限（`maxFieldEnemies`）とは別枠で、**首討伐後の我が家からのみスポーン可能な専用バジェット枠**（例：首1本=+2体、首2本=+3体、首3本=+4体）を設ける。
2. **遠方残存敵の優先パージ（入れ替えスポーン / `evictDistantEnemyOnHomeSpawn`）**:
   - 家湧き専用枠すら埋まっている状態で `spawnFromHome` がトリガーされた場合、プレイヤーおよび我が家から最も遠い位置（マンハッタン距離が閾値以上）にいる非交戦中の雑魚敵1体を消去（ディスポーン）し、我が家の隣接マスへ新規モンスターを優先的に湧かせる。
   - これにより、パフォーマンスや画面内の過剰な混雑を防ぎつつ、**「首討伐後の我が家に近づくと必ず敵が湧き出して迎え撃ってくる」**緊張感を100%保証する。

---

### 3.2 課題2への対策：EXP / STR 成長カーブと被ダメージ軽減の適正化 (`progressionConfig`)

#### 問題の所在
現行の `Enemy.ts` における獲得EXP計算式 `Math.floor(this.stats.baseDef / 2) + 50` では、終盤モンスター（DEF 200,000〜520,000）を1体撃破した瞬間に EXP が +100,000〜+260,000 跳ね上がる。
EXPは「最大HPの上昇」と「被ダメージ軽減（実質DEF = EXP依存）」の両方に直結するため、1体倒した瞬間にすべての敵からノーダメージになるか、逆にそこに至る前は即死するかという極端な「0か100かのインフレ階段」が発生している。

#### 解決メカニズム
1. **獲得EXP減衰カーブ (`expCurveMode` & `expDampingPower`)**:
   - `'CLASSIC_LINEAR'`: 原作・現行準拠の線形比例（`baseDef * ratio + 50`）。
   - `'DAMPED_POWER'`: 高DEF帯での極端な跳ね上がりを抑えるべき乗減衰式（例: `floor(scale * Math.pow(baseDef, 0.75)) + 50`）。これにより、中盤〜終盤のモンスター撃破時のEXP上昇を滑らかな成長曲線に収める。
   - `'PHASE_CAPPED'`: ドラゴンの首討伐数（0〜3本）に応じて、1回の戦闘で得られる最大EXPや累積EXPの実効キャップを段階的に解放するモード。
2. **EXPによる被ダメージ軽減スケーリング (`expDefenseMitigationRatio`)**:
   - 敵から受けるダメージ計算におけるプレイヤーEXPの防御寄与率を調整可能にし、HP上限の伸びと被ダメ軽減のバランスを分離チューニングできるようにする。
3. **パワーストーンSTR複利成長の調整 (`powerStoneGrowthRate` & `powerStoneFlatBonus`)**:
   - マップ内の宝箱総数や宝物庫の配置密度に合わせ、1個あたりの複利成長率（現行 `0.35`）と固定加算値（現行 `+2000`）をマップ単位で調整可能にする。

---

### 3.3 課題3への対策：非消耗アイテム総数キャップとゴースト配置数 (`resourceCapConfig`)

#### 問題の所在
現行の `ChestSystem.ts` では、8歩周期以外の宝箱開錠時に `1/8` の確率で装備品（十字架・指輪・鍵）が上限なく排出される。特に「十字架（`CROSS`）」は手持ちで完全無敵・床置きで墓封鎖＆死神成仏という強力な効果を持つため、マップ内に何個も出現すると主要な墓や通路をすべて封鎖できてしまい、ゲームバランスが崩壊する。また、ゴースト（`Ghost`）の数もマップ構造によらず固定（2体）となっている。

#### 解決メカニズム
1. **非消耗アイテムの初期配置数（Min）とマップ内総数上限（Max Cap）の厳格管理**:
   - 各非消耗アイテム（`CROSS`, `RING`, `KEY`, `SWORD`）に対して、**「初期配置数 (`initialCount`)」**と**「マップ上に同時に存在できる最大総数 (`maxTotalCap`)」**を定義する。
   - **動的カウント判定**: `床上の該当アイテム数 + プレイヤー所持分 + ゴースト保持分` の合計が `maxTotalCap` に達している場合、`ChestSystem` で装備品枠（1/8）が抽選されても排出をブロックし、代わりに消耗品（魔法の壺 `POTION` または金貨 `COIN` / パワーストーン `POWER_STONE`）へフォールバックさせる。
   - 例：狭路迷路（`NARROW_MAZE`）では十字架1個でも通路封鎖力が絶大なため `crossMaxCap: 1` に制限し、墓が多いピラー広場（`PILLAR_GRID`）では `crossMaxCap: 2〜3` を許容するなど、トポロジーに応じた制御を行う。
2. **ゴースト初期配置数と速度の制御 (`ghostCount` & `ghostMoveIntervalMs`)**:
   - マップの開放度やアイテムの孤立度に応じて、ゴーストの同時出現数（例：0〜4体）および滑空インターバルを指定可能にする。
   - 密室宝物庫が多いマップではゴーストを増やして「壁の向こうからアイテムを運び出してもらう（または `JUMP` の足場にする）」機会を増やし、逆に狭路マップでは理不尽なひったくりを抑えるため1体に絞るといった調整が可能になる。

| **EXPカーブ (`expCurveMode`)** | `DAMPED_POWER` | `DAMPED_POWER` | `DAMPED_POWER` | `PHASE_CAPPED` |

### 3.5 ユーザー向け高レベル設定：「難易度 × プレイ時間イメージ」による自動プリセット合成 (`PlayStylePreset`)

一般プレイヤーやマップ作成者が、毎回細かい内部数値（`expDampingExponent` や `powerStoneGrowthRate` など）を手動で調整しなくても済むよう、UIの最上位には**直感的な2軸設定（「難易度」×「ゴールまでのプレイ時間イメージ / ペース」）**を用意する。

ユーザーが選択した「トポロジー」「難易度」「プレイ時間イメージ」の3要素から、ファクトリ関数（`TuningPresetResolver.resolve(topology, difficulty, pacing)`）が裏側の `DungeonTuningParams` を自動合成する2層構造（簡単設定 ＋ 上級者向け詳細オーバーライド）とする。

#### ① プレイ時間・テンポ設定 (`PlayPacingMode`) の3段階定義

| モード名 | 時間イメージ (目安ターン数) | 自動調整される内部パラメータの振る舞い |
| :--- | :---: | :--- |
| **`BLITZ` (短時間・高速決着)** | **約 5〜10 分**<br/>(約 400〜800 ターン) | ・**高倍率の成長曲線**: パワーストーン複利成長率を高め（例: `0.55`、約7〜8個でドラゴン突破可能）、EXP獲得量も1.8倍にブーストして早期に `BREAK` / `斜め移動` を解禁。<br/>・**コンパクトな導線**: 家からドラゴンまでの距離を近めに生成し、初期から剣・鍵・指輪を近傍配置。<br/>・**凝縮されたクライマックス**: 育成時間を大幅短縮しつつ、首討伐後の家湧きラッシュと王冠脱出のスリルを短時間で一気に味わえるモード。 |
| **`STANDARD` (標準プレイ)** | **約 15〜25 分**<br/>(約 1,200〜2,000 ターン) | ・**バランス型の成長曲線**: パワーストーン約14〜15個でドラゴン突破、減衰EXPカーブにより序盤・中盤・終盤のモンスターと段階的に渡り合う標準設計。<br/>・**適度なパズル＆開拓**: 密室宝物庫の開拓や十字架での墓封鎖など、ドラスレ本来の陣取りと育成サイクルをバランス良く体験。 |
| **`MARATHON` (じっくり長編・本格派)** | **約 35〜60 分**<br/>(約 3,000〜5,000 ターン) | ・**緩やかな成長と計画的開拓**: パワーストーン複利成長率を緩やかに設定（例: `0.22`、22〜25個必要）し、`PHASE_CAPPED` により首を1本ずつ倒しながら段階的に上限解放。<br/>・**高密度な迷宮と資源管理**: 宝箱や墓の総数を増やし、複数のセクターや宝物庫を計画的に攻略・掘削して少しずつ前線を押し上げる、原作PC-88版の重厚なプレイ感を再現。 |

#### ② 難易度設定 (`DifficultyMode`) との掛け合わせマトリクス

- **「難易度 (`EASY / NORMAL / HARD`)」** は主に**「生存の厳しさ・パズルのシビアさ」**（初期ブートストラップの安全性、十字架や鍵の上限数、敵ATK倍率、家湧き専用枠の多さ、ゴーストのひったくり頻度）を制御する。
- **「プレイ時間 (`BLITZ / STANDARD / MARATHON`)」** は主に**「ゴールまでの距離・育成スピード」**（パワーストーン成長率、EXP獲得倍率、ドラゴンHP/DEFスケーリング、初期宝箱の密集度）を制御する。
- これにより、例えば**「HARD × BLITZ（10分で終わるが、十字架が1個しかなく家湧きも激しい高密度サバイバル）」**や**「EASY × MARATHON（敵の攻撃は穏やかで十字架も多いが、広大な迷宮を40分かけてじっくり開拓する探索モード）」**といった多彩な遊び方をワンクリックで選択できる。

## 4. 「プロシージャル生成 × プリセット共有 × インスペクタ診断」のアーキテクチャ設計

### 4.1 データ構造の最小化（Seed + Options 方式 / `MapPresetData`）

マップ全体（4,096マス）のタイル配列を保存・送信するのではなく、**「生成シード値・トポロジー・難易度・ペース・アーキタイプ・プレハブ設定」**のみを記録することで、決定論的PRNGにより同一の64×64迷宮を100%再現する。

```typescript
export interface MapPresetData {
  id: string;
  name: string;
  description?: string;
  createdAt: number;
  isCurated?: boolean;
  seed: number;
  options: {
    difficulty: 'EASY' | 'NORMAL' | 'HARD';
    pacing: 'BLITZ' | 'STANDARD' | 'MARATHON';
    topology: 'STANDARD_ROOMS' | 'PILLAR_GRID' | 'NARROW_MAZE' | 'SPIRAL_LABYRINTH' | 'FORTRESS_ARENA' | 'MULTI_SECTOR';
    archetype?: 'BALANCED' | 'SANCTUARY' | 'WARP_NEXUS' | 'ARMORY' | 'SIEGE';
    dragonPrefab?: 'FORTRESS_7x7' | 'COMPACT_5x5';
    homePrefab?: 'STANDARD_ROOM' | 'COMPACT_3x3';
  };
}
```

#### ファイルサイズと共有の利点:
* **データサイズ**: 4,096マスのタイルデータが不要なため、**わずか百数十バイト**で収まる。
* **1行共有コード (`DS1MAP:...`)**: Base64エンコードにより、1行の短いテキストコードとしてクリップボード経由で即座にエクスポート・インポート可能（`MapPresetManager`）。

---

### 4.2 カスタム生成診断プレビュー & インスペクタ解析ワークフロー

1. **タイトル画面「カスタム生成＆診断プレビュー」 (`DOMUIManager`)**:
   - シード値、トポロジー、難易度、ペース、アーキタイプを指定し、ゲーム開始前にワンクリックで `ProceduralMapGenerator.validateSolvability()` を実行。
   - 初期到達性、重複ゼロ、ドラゴン要塞クリアランス、宝箱・墓の数、およびランダム開封（1/8）基準での想定最大到達STRを即座に診断表示する。
2. **インゲーム「ダンジョン＆成長インスペクタ」 (`InspectorModal` / `[I]` キー)**:
   - プレイ中いつでも 64×64 全体マップの縮小俯瞰、空間開口率・ブロック密度、現在適用されている `DungeonTuningParams`、およびパワーストーン複利成長曲線グラフをリアルタイムに確認可能。
3. **ヘッドレス・プレイシミュレーションとの連携**:
   - 構造メトリクスだけでは分からない「動的なゲームバランス（後半の家湧きラッシュの苛烈さ、EXP/STRの伸び方、十字架による墓封鎖の影響）」を検証するため、[`headless_and_multi_frontend.md`](./headless_and_multi_frontend.md) で規定する**ヘッドレス自動プレイBot（`AutoPlayBot`）**と直結する。

---

## 5. 公式おすすめプリセット (`CURATED_PRESETS`) の構成

多彩なプロシージャル生成 × アーキタイプ × プレハブの組み合わせにより、タイトル画面から即座に遊べる5つの代表的な迷宮プリセットを標準搭載している：

* **👑 龍の大広間 (`curated_grand_hall`)**:
  - `MULTI_SECTOR` / `NORMAL` / `STANDARD` / `BALANCED` (`FORTRESS_7x7`)
  - 広大な大広間の中央に3首ドラゴンが鎮座する王道マップ。
* **🐉 回廊奥の古龍 (`curated_corridor_lair`)**:
  - `NARROW_MAZE` / `HARD` / `BLITZ` / `BALANCED` (`COMPACT_5x5`)
  - 細長い迷路回廊の最深部にドラゴンが巣食う短期決戦マップ。
* **✝️ 聖域の守護者 (`curated_sanctuary_guardian`)**:
  - `MULTI_SECTOR` / `NORMAL` / `MARATHON` / `SANCTUARY` (`COMPACT_5x5`)
  - 十字架が多数配置され、4体のゴーストから王冠を守る結界戦術が鍵となる長編マップ。
* **⚔️ 四神の武器庫 (`curated_armory_nexus`)**:
  - `PILLAR_GRID` / `NORMAL` / `STANDARD` / `ARMORY` (`FORTRESS_7x7`)
  - 多数の予備剣とピラー回廊を活かして激戦を制するマップ。
* **🌀 螺旋迷宮の咆哮 (`curated_spiral_roar`)**:
  - `SPIRAL_LABYRINTH` / `HARD` / `STANDARD` / `BALANCED` (`COMPACT_5x5`)
  - 渦巻き状の回廊が続く高密度ラビリンス。岩押しと `BREAK` 掘削の腕が試される。

## 6. まとめ

1. **トポロジー拡張 & `DungeonTuningParams` 基盤**:
   - `ProceduralMapGenerator.ts` による全6種トポロジー＆9セクター動的配置と、`SpawnSystem`・`CombatSystem`・`ChestSystem` へのパラメータ統合。
2. **ヘッドレスBotシミュレーションによる定量検証**:
   - トポロジーごとのクリア率・家湧き発生率・EXP推移を `AutoPlayBot` で計測し、54通りのプリセット値を最適化。
3. **プリセット共有 (`MapPresetManager`) とリアルタイム解析 (`InspectorModal`)**:
   - おすすめプリセット、ユーザー保存、および `DS1MAP:` 共有コードによる軽量なマップ共有体験の実現。
